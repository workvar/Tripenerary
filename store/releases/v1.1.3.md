## v1.1.3

Fix Play upload signing: release AABs are now signed with the upload keystore. Previous `v1.1.2` bundles were debug-signed because `expo prebuild --clean` wiped `android/` (keystore + custom `signing.gradle`) before Gradle ran.

### Highlights

- **Release signing fixed.** Skip `expo prebuild --clean` on tagged builds, decode the upload keystore onto the committed `android/` tree, require release signing in Gradle, and reject any artifact still signed `CN=Android Debug`.
- **First Play-ready AAB.** Use this build for the initial Google Play Console upload.
- **Same first-release product.** Trips from JSON, day schedule, maps, offline PDFs, optional sync — see `store/FIRST_RELEASE_NOTES.md` / `store/whatsnew/whatsnew-en-US`.

### Added

- CI step **Verify release signing (reject debug)** on APK and AAB
- `-Ptripenerary.requireReleaseSigning=true` so Gradle fails instead of falling back to debug

### Changed

- Release workflow no longer runs `expo prebuild --clean` (it destroyed release signing)
- Missing keystore / password secrets now fail the release job
- Version bump to `1.1.3` / `versionCode` `10103`

### Upgrade notes

- Discard any `v1.1.2` AAB already rejected by Play as debug-signed; upload `tripenerary-1.1.3.aab` instead.
- Register this upload keystore’s SHA-1 on the Google Maps Android API key.
- Play Console service-account invite is still required for the automated Play job (`The caller does not have permission`).
