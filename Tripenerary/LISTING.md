### Full description

```
Tripenerary turns your travel itinerary into a clean, day-by-day companion on your phone.

Paste a link to your itinerary file. The app downloads it, saves a copy on the device, and opens straight to the day you are on: times, places, stays, tickets and notes, all in one screen. Change the file, pull to refresh, and the phone catches up. Keep several trips side by side.

WHAT IT DOES

• Trip library — one card per trip, sorted so whatever is happening now comes first. Badges tell you "Day 3 · Now", "In 12 days" or "8 days ago".
• Day view — hero photo, base city, summary, and the schedule as full-width blocks with the time up top.
• Date strip — a scrollable strip of every day within thumb reach, with a "Jump to today" shortcut when you wander off.
• Maps — every location gets an embedded preview plus one tap to open Google Maps or start directions.
• Stays — which hotel you are checked into that day, with dates, confirmation number and a tappable phone number.
• Tickets and documents — flight tickets, hotel confirmations, show tickets and insurance PDFs open in your usual viewer and stay cached for later.
• Photos — trips, days, activities and stays can all carry images. Tap to open full screen, pinch to zoom, flick down to close. Turn them off entirely if you prefer.
• Trip info — emergency numbers, every stay, and practical notes on visas, money and weather.
• Daily refresh — each trip re-checks itself once a day, or on demand.
• Optional account sync — sign in to carry your trips and preferences to another phone. Skip it and everything stays on the device.

BUILT FOR BAD SIGNAL

Once a trip is saved it opens with no connection at all: schedule, stays, notes and any document you have already opened. Landing in a new country with no data plan is the case this app was designed around.

BRING YOUR OWN ITINERARY

Nothing about any particular trip is baked in. Your itinerary is a plain JSON file you host anywhere, a GitHub Gist works fine, so you stay in control of the content and can update it mid-trip without republishing an app.

NO ADS. NO TRACKING.

There is no advertising, no analytics and no data collection. Your itinerary lives on your phone, and in your own cloud account only if you choose to sign in.
```

### Screenshots

Play requires real captures of the running app; mockups and device frames are
rejected. Two scripts handle it:

```bash
npm run screenshots -- phone        # capture over adb, prompts per screen
npm run screenshots:fit             # resize every profile to Play dimensions
```

`capture-screenshots.mjs` puts SystemUI into demo mode first, so the status bar
shows 12:00, full battery and full signal with no notifications, which is what
Play's guidelines ask for. Raw captures land in `store/screenshots/<profile>/`;
`fit-screenshots.py` writes Play-ready copies to `.../play/`.

Profiles, the shot list and the Play Console alt text live in
`scripts/screenshot-profiles.mjs`.

Suggested emulators:

| Profile | AVD |
|---|---|
| `phone` | Pixel 6, API 34 |
| `tablet7` | Nexus 7, API 34 |
| `tablet10` | Pixel Tablet, API 34 |
| `chromebook` | Desktop / Chrome OS AVD, or a real Chromebook with ADB debugging on |

**All profiles are 9:16 portrait.** `MainActivity` is locked to
`android:screenOrientation="portrait"`, so there is no landscape UI to capture.
Play accepts 9:16 on large screens, so this is fine, but if you ever unlock
landscape, add 16:9 variants for `tablet10` and `chromebook` since those slots
display better in landscape.

Use a sample trip whose images are public domain or CC0, or turn **Show images**
off in Settings before capturing so you do not ship copyrighted third-party photos
in the listing.

## Form factors (tablets and Chromebooks)

Screenshots alone do not enable these. In Play Console, go to **Release > Setup >
Advanced settings > Form factors** and add **Tablets** and/or **Chrome OS**.
Each one runs its own pre-launch checks before the listing section unlocks.

Before opting in, know that the current build is deliberately phone-shaped:

| Constraint | Where | Effect on large screens |
|---|---|---|
| `android:screenOrientation="portrait"` | `AndroidManifest.xml` | The app will not rotate. On a Chromebook it opens in a portrait window the user cannot widen. |
| No `resizeableActivity` declared | `AndroidManifest.xml` | Defaults to `true` on API 24+, so windowed mode works, but the portrait lock still constrains it. |
| Layouts are single-column | `src/screens/` | Renders as a wide phone rather than using the extra width. |

That is a valid, publishable state and Play accepts 9:16 screenshots for these
slots. But Play's large-screen app quality tiers will grade it low, which limits
promotion in the tablet and Chromebook sections of the store.

If you want a better grade later, the order of work is: unlock landscape, let
the day view use a two-pane layout on wide windows, then re-capture at 16:9.
Until then, opting in is optional — leave the sections empty and the phone
listing still serves those users.

Chromebook also requires that the app not depend on hardware Chromebooks lack.
Tripenerary only declares `INTERNET` and `ACCESS_NETWORK_STATE`, so nothing
blocks it.
